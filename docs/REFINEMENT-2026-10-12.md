# 豆包落地页优化说明 · 2026-10-12

这次保留写实豆包人物与暖色视觉，把页面主线整理为：人物开场 → 居中对话 → 能力工作台 → 日常场景 → 轻互动 → 回到对话。

## 已实现的交互

- 双眼轻微跟随指针，使用平滑阻尼；原素材的微笑、眨眼继续来自视频。
- 按住脸颊后可小幅拖动，松手回弹；限定脸颊区域，保护眼睛、鼻子及背景。
- 触屏保留长按轻触反馈；滑动超过阈值让位给页面滚动。
- 暂停/恢复人物动态，记住本次浏览偏好；遵循系统“减少动态效果”。
- 人物退出首屏或页面进入后台时暂停视频；默认不再加载旧角色立绘。
- 聊天增加停止回复、新对话、草稿保留、中文输入保护；保留回复复制和追问。
- 页尾按钮直接回到聊天区。
- 音效默认静音，可由导航按钮主动打开。

## GIF 能不能继续做捏脸和眼神跟随？

可以做轻度 2D 互动，现版本已经落地。但 GIF/视频已经把眼睛和皮肤合成成像素，没有独立眼球、深度或完整的被遮挡纹理。因此不能把它等同于真正三维转眼、转头或面部肌肉模拟。

仓库包含同名的完整素材：GIF 2,805,966 字节，WebP 835,658 字节，MP4 255,332 字节。当前以同内容的 MP4 做动态纹理，比 GIF 小约 91%，静态 WebP 作为首屏与视频失败时的兜底。原始 GIF/WebP 均保留。**不把 GIF 直接画到 Canvas 作为可靠动画方案**：[HTML 标准](https://html.spec.whatwg.org/multipage/canvas.html#image-sources-for-2d-rendering-contexts)规定，动画图像作为 Canvas 2D 图像源时使用默认图或第一帧；视频则使用当前播放帧。

本次眼区采用针对这段 5 秒素材的六组近似标定，局部采样位移控制在数个源像素内；眨眼附近减弱形变。它是“看向指针”的轻度视觉模拟。更换素材、增加大幅转头后，应重新标定，不能沿用这些坐标。

更自然的下一步：离线用 MediaPipe Face Landmarker 对每帧提取脸部/眼部位置，导出轨迹与眼睑遮罩，再在前端读取轨迹驱动局部形变。这样不用在访客浏览时跑完整识别模型。MediaPipe 提供关键点、表情系数与变换矩阵，**检测本身不会补出新的眼白或瞳孔**；遮挡明显时仍需补充素材，或换成带独立眼球与表情绑定的 3D 模型。这一方案是基于官方能力说明的工程推断。

参考：[MDN：视频作为 WebGL 动态纹理](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/Tutorial/Animating_textures_in_WebGL)、[Google：Face Landmarker Web](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker/web_js)、[MDN：drawImage](https://developer.mozilla.org/en-US/docs/Web/API/CanvasRenderingContext2D/drawImage)。

## 后续值得优先升级的部分

1. **真实聊天的服务端代理。** 现有 GitHub Actions 会把 `VITE_DIFY_API_KEY` 注入静态前端包；公开页面中的这类值可被访客读取。应迁移到服务端代理，再加请求限速、超时、重试和清晰的失败提示。本次保留既有连接配置，没有迁移服务端或轮换凭据。
2. **真实语音链路。** 用用户主动开启的麦克风录音接 ASR，再接 TTS；人物嘴型依据音频音素驱动。当前语音按钮只是明确标识的交互示例，不能冒充真实识别。
3. **更精确的眼神。** 离线逐帧关键点与眼睑遮罩，比全脸摆动更能提升写实感；先小范围验证，避免眼白拉扯。
4. **有产出的能力演示。** 让写作可下载结果，让真实附件解析展示来源页码，让图像演示展示实际前后图。现有沙盒的文件/图像结果仍为演示内容。
5. **少量状态动效。** 思考、生成、完成、失败四种明确反馈，配合短促声波或描边即可。继续增加导航、烟花和大面积闪光会削弱人物与内容。
