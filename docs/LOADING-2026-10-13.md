# 等一个微笑 · 加载开场

按用户要求，在首页人物画面准备好以前展示完整的加载体验。沿用暖白、深墨与围巾红，以内联 SVG 小豆包、椭圆轨道和三枚灵感标签构成开场。眨眼、轻跳、围巾摆动和指针眼神让等待有回应；点击可打招呼，触摸与键盘也可操作。

## 真实进入条件

- HTML 自带加载画面与关键样式，入口脚本下载前就能展示；正文暂时隐藏。
- 读取静态封面解码、视频首帧和人物绘制状态，显示三个准备步骤。数字表示步骤数量，不表示下载字节百分比。
- 默认模式等待视频已经解码、作为纹理被实际渲染后揭幕。`faceRendered` 标记移到 `stage.render()` 之后，不再以图片请求结束代替渲染完成。
- 保持初始取景，等待时锁住滚动与正文交互。完成后恢复滚动、正文及焦点。
- 加载幕柔和淡出，然后再播放原首页的文案入场，脸部先出现。
- 开场动画的最短节奏约 950ms，退出约 640ms；如果加载更久，不再额外补足等待时间。时间本身不满足进入条件。

## 加载优先级

首屏所需的渲染模块并行请求。小体积静态封面在 HTML 中优先加载；身体照片等首页后续资源在揭幕后开始请求，减少与脸部素材竞争。没有增加任何大型动画素材或第三方运行依赖。

## 降级

- 视频无法播放：等静态封面确实解码、绘制后进入，状态改为静帧。
- 渲染模块失败：确认 DOM 封面已经解码后展示静态首页。
- 系统要求减少动态：禁用加载循环动效与视频自动播放，等静态画面准备好后直接揭幕。
- 超过 12 秒：继续等待，不自动放行；提供重新加载，以及静态封面已经准备好的情况下的「先看静态微笑」。
- 连静态脸图也不可用：保留加载页和重试入口，避免进入缺脸的空白首页。
- 入口脚本无法下载：HTML 中的独立提示在 15 秒后提供重试。无 JavaScript 时显示静态正文。

## 复验

运行生产构建后启动预览，执行 `pnpm verify:loading`。浏览器验证：慢视频、慢渲染模块、入口脚本未到达、手机排版、视频失败、渲染失败、减少动态、脸部全部素材失败、超慢连接的主动静帧选择。`pnpm verify` 继续覆盖人物身体、捏脸、聊天、产品介绍和玩法。
